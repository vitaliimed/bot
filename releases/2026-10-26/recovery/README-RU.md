# Исправление очереди — 26 октября 2026

## Что проверено

Публичный /health рабочего сервиса ответил ok=true, version=v2-2be149db8aad-peak50. Это подтверждает доступность приложения, но не доставку новостей. Из последнего отчёта соседнего чата известны успешные проверки Gemini, Haimaker и Cloudflare. Полные текущие настройки Firestore и состояние каждой карточки из этой среды недоступны.

В доступном исходном коде найдены и воспроизведены причины зависания:

1. После сбоя перевода материал мог остаться pending + translation_missing. Подключение рабочего ИИ не возвращало его автоматически на обработку.
2. Выбранный проверяющий ИИ не запускался для украинского оригинала, потому что оригинал пропускал перевод. При включённом reviewer карточка оставалась без одобрения.
3. Перевод из кеша мог сохранять старую неудачную проверку ИИ, не выполняя проверку повторно.
4. Отдельный обработчик публикаций посещал только каналы с запланированными заданиями. Готовая автоматическая новость без такого задания ждала полного сбора источников.

Эти дефекты исправлены. Их наличие в коде не доказывает единственную причину именно вашей текущей очереди: рабочие настройки и другие блокировки покажет /repair.

## Что делает исправление

- Добавляет один модуль app/queue_recovery.py и его подключение в конце app/main.py.
- Оставляет существующие провайдеры, ключи, Haimaker, языковые исправления, режим peak50, источники, модели, настройки и историю.
- Повторяет подготовку актуальных зависших материалов ограниченными порциями. Между автоматическими повторными восстановлениями одной карточки — 15 минут, до трёх восстановлений при неизменной конфигурации. Сохраняет счётчик и причину.
- При изменении настроек/подключений позволяет новый ограниченный цикл. Реальные запросы дополнительно ограничиваются существующими дневными и месячными лимитами.
- Не восстанавливает опубликованные, истёкшие, отменённые или требующие сверки доставки материалы.
- Проверяет украинский оригинал и кешированный перевод выбранным reviewer, не переводя их повторно ради проверки.
- Публикует готовую автоматическую очередь через существующий обработчик dispatch, соблюдая автоматический режим, фильтры, язык, модерацию, интервалы, квоты и защиту от дублей.
- Добавляет постоянную кнопку «🩺 Восстановить очередь» и /repair: текущая очередь, разрешённые настройками переводчики, причины задержки и подтверждаемое восстановление до 25 карточек. Фактическая порция также ограничена processing_batch_size.

Исправление не включает платные модели автоматически и не подменяет украинский перевод финским оригиналом. Наличие разрешённого подключённого провайдера не гарантирует его баланс или исправность API.

## Установка без Git

Нужен текущий исходный проект, из которого собрана ваша последняя версия, обычно ~/projects/bot. Не распаковывайте старые полные версии поверх этого проекта: это может удалить более поздние языковые и ИИ-исправления.

Загрузите finland-bot-recovery-20261026.zip в Cloud Shell и выполните:

```bash
(
set -e
ARCHIVE="$HOME/finland-bot-recovery-20261026.zip"
if [ ! -f "$ARCHIVE" ]; then
  ARCHIVE="$HOME/projects/bot/finland-bot-recovery-20261026.zip"
fi
if [ ! -f "$ARCHIVE" ]; then
  echo 'Сначала загрузите finland-bot-recovery-20261026.zip'
  exit 1
fi
PATCH_DIR=$(mktemp -d "$HOME/finland-bot-recovery-XXXXXXXX")
unzip -q "$ARCHIVE" -d "$PATCH_DIR"
bash "$PATCH_DIR/bot-recovery-20261026/update.sh" "$HOME/projects/bot"
)
```

Установщик проверяет наличие нужных функций, сохраняет копию изменяемого исходника, применяет патч, проверяет синтаксис и разворачивает кандидата без трафика. Только после проверки health/version и защищённого отчёта новой функции переключает трафик. Затем выводит диагностику и точную команду отката на предыдущие доли трафика.

Скрипт не изменяет расписания Scheduler. finland-news-collect, finland-events-collect и finland-news-dispatch должны быть ENABLED; их состояние выводится в конце. При проблеме на проверке кандидата новый трафик не переключается.

## Первые действия

1. /start → Новости → /repair.
2. Прочитайте причины: нет перевода, модерация, интервал, дневной лимит и т. д.
3. «Восстановить очередь» → подтверждённый запуск отправляется существующему Scheduler. Кнопка не публикует неподготовленный материал и не отменяет фильтры.
4. Подождите несколько минут → /repair → «Готовые новости». Проверьте появление украинского текста, картинки и публикации.
5. Для срочного материала: карточка → выбрать канал → точное превью → подтвердить. Для группы — существующая массовая публикация.
6. Повторите для Событий. Истёкшие события не следует восстанавливать как предстоящие.

Если в отчёте «Включено ручное подтверждение всех материалов», бот выполняет вашу настройку. Отключите её только осознанно через настройки, либо публикуйте подтверждённые карточки вручную. Если «Нет разрешённых переводчиков», нужно исправить режим/порядок моделей, а не повышать количество публикаций.

## Независимая диагностика без обновления

Можно сначала распаковать архив и запустить diagnose.py против текущего сервера. До установки патча новый endpoint вернёт 404 — это ожидаемо. Для текущего старого сервера используйте уже существующий `bash scripts/diagnose.sh` в проекте.

После установки команда diagnose.py из архива показывает отчёт без вызова платных моделей и без отправки новостей. Не присылайте API-ключи: достаточно вывода диагностики.
