# Обновление бота: новости + события

## 1. Сначала проверка сервера

В Google Cloud Shell скопируйте целиком:

```bash
(
set -e
cd "$HOME/projects/bot"
git pull --ff-only
bash scripts/diagnose.sh
)
```

Проверка читает биллинг, Cloud Run, последнюю сборку, webhook, очередь Telegram, права бота в обоих каналах, задания Scheduler и свежие логи. Она не публикует сообщения. Значения ключей не выводятся. До обновления отсутствие `finland-events-collect` нормально.

Нормальный результат: `Cloud Run: True`, health `ok: true`, оба `can_post_messages: True`, очередь webhook обычно 0. Старая ошибка webhook сохраняется в Telegram даже после исправления: смотрите её дату и свежие логи. Успешный health сам по себе не проверяет доступность ИИ.

## 2. Установить подготовленное обновление

```bash
(
set -e
cd "$HOME/projects/bot"
git pull --ff-only
PROJECT_ID=winged-ratio-377512 \
REGION=europe-north1 \
EVENTS_CHANNEL_ID=@eventhsl \
bash scripts/upgrade-all.sh
)
```

Скрипт повторно проверяет сервис и права бота, собирает код в Cloud Run, добавляет каталог источников, переносит старые записи без повторной публикации, настраивает два задания Scheduler и проверяет новый сервис. В конце выводится команда отката к предыдущей ревизии. Существующие ключи остаются в Secret Manager. Для управления включается `ADMIN_AUTH_MODE=channel_admins`.

| Поток | Канал | Обязательная подпись | Начальные параметры |
|---|---|---|---|
| Новости | `@suominewsua` | `#suominewsua` | Украинский, 12/день, интервал 60 минут |
| События | `@eventhsl` | `#eventhsl` | Украинский + финский, 20/день, интервал 30 минут |

Сохранённые настройки новостей имеют приоритет над начальными значениями. Автопубликация событий первоначально выключена. Новостная автопубликация сохраняет прежнее состояние. Бот должен быть администратором обоих каналов с правом публикации. Для управления событиями пользователь также должен иметь права публикации в обоих каналах. Личный Telegram ID вручную вводить не требуется.

Откат кода не удаляет сохранённые материалы и настройки. При возврате к старой версии, которая не знает о событиях, сначала приостановите новое задание:

```bash
gcloud scheduler jobs pause finland-events-collect \
  --project=winged-ratio-377512 --location=europe-west1
```

Затем выполните команду `update-traffic`, напечатанную при обновлении. После возврата на новую версию возобновите задание командой `gcloud scheduler jobs resume finland-events-collect --project=winged-ratio-377512 --location=europe-west1`.

## 3. Подключить OpenAI и дополнительные ИИ

После обновления это можно сделать прямо в боте: `/ai` → провайдер → «Добавить / заменить ключ» → отправить ключ → «Проверить текстовый ИИ». Общими ключами управляет владелец основного канала. Ключи общие для двух каналов; отключение провайдера и очередь отдельные. Подробно: [постоянное меню и управление ИИ](MENU-AI-RU.md).

Для одного OpenAI:

```bash
cd "$HOME/projects/bot"
bash scripts/connect-ai.sh openai
```

Для всех поддерживаемых провайдеров:

```bash
cd "$HOME/projects/bot"
bash scripts/connect-ai.sh all
```

Скрипт по очереди запросит ключи. Вставьте ключ и нажмите Enter. Символы не показываются — это нормально. Пустой Enter пропускает провайдера и сохраняет его прежний ключ, если он уже был подключён. Необязательно регистрироваться во всех сервисах: достаточно одного рабочего ключа; два или три дают запасной вариант.

Секреты записываются в Google Secret Manager; подключение начинает использоваться новыми запросами без пересборки и перезапуска Cloud Run. Сначала обновите сервер, затем используйте новый `connect-ai.sh`. Наличие ключа ещё не подтверждает баланс, квоту или доступ к выбранной модели.

### Где получить ключ OpenAI

1. Откройте <https://platform.openai.com/> и войдите в свой аккаунт OpenAI.
2. Выберите или создайте API-проект для этого бота.
3. Откройте <https://platform.openai.com/api-keys>.
4. Создайте новый secret key (`Create new secret key`), например с названием `finland-news-bot`.
5. Скопируйте ключ сразу после создания. Если он утрачен, создайте новый.
6. В разделе Billing API-платформы подключите оплату/кредиты, если они требуются вашему аккаунту. Настройте бюджет и уведомления; уведомления сами по себе не являются жёстким ограничением расходов.
7. Вставьте ключ в запрос скрипта `connect-ai.sh openai` в Cloud Shell.

Подключается OpenAI API. Это не копирование текущего диалога ChatGPT в Telegram. Подписка ChatGPT Plus и расходы API оплачиваются отдельно. Внутри бота OpenAI работает редактором, генератором изображений и, через `/ask`, помощником администратора. `/ask` не получает доступ к поиску, настройкам или публикации и не знает текущих событий без предоставленного контекста.

### Какие ИИ поддерживаются

| Провайдер / код в настройках | Где получить ключ | Начальная текстовая модель | Роль |
|---|---|---|---|
| OpenAI / `openai` | <https://platform.openai.com/api-keys> | `gpt-4.1-mini` | Текст, проверка, изображения |
| Google / `gemini` | <https://aistudio.google.com/api-keys> | `gemini-3.5-flash-lite` | Текст, проверка, изображения |
| Groq / `groq` | <https://console.groq.com/keys> | `openai/gpt-oss-20b` | Текст и проверка |
| DeepSeek / `deepseek` | <https://platform.deepseek.com/> → API keys | `deepseek-flash` | Текст и проверка |
| Mistral / `mistral` | <https://console.mistral.ai/> → API keys | `mistral-small-latest` | Текст и проверка |
| OpenRouter / `openrouter` | <https://openrouter.ai/keys> | `openai/gpt-4.1-mini` | Доступ к моделям разных компаний |

Это технически поддерживаемые подключения, а не обещание бесплатного доступа. Доступность моделей и тарифов зависит от аккаунта. OpenRouter не делает платную модель бесплатной. Для изображений настроены OpenAI `gpt-image-2.5-flare` и Gemini `gemini-3.1-flash-image`; право доступа проверяется реальным запросом.

### Как искать и добавлять модели

1. Открывайте официальный раздел API / Models / Pricing провайдера. Пользовательский чат и API могут иметь разные тарифы и ключи.
2. Выбирайте модель с текстовым API и JSON-ответами. Для фото нужна именно генерация изображений, а не только распознавание фотографий.
3. Скопируйте точный **API model ID**, а не маркетинговое название.
4. Подключите ключ через скрипт. В боте выберите канал, затем `/settings` → «ИИ».
5. Например, для OpenAI: `/set openai_model gpt-4.1-mini`. Аналогично доступны `gemini_model`, `groq_model`, `deepseek_model`, `mistral_model`, `openrouter_model`.
6. Задайте порядок. Он настраивается отдельно для каждого канала:

```text
/set ai_order openai,gemini,groq,deepseek,mistral,openrouter
/set ai_timeout 12
/set image_order openai,gemini
```

Первый провайдер без ключа пропускается. При перегрузке, ошибке или превышении времени ответа бот пробует следующего. После ошибки действует короткая пауза для этой модели; при 401/403/404 — более длинная. Пауза локальна экземпляру Cloud Run; после перезапуска она сбрасывается. Если недоступны все, материал остаётся в `awaiting_ai`, а не исчезает. До трёх попыток, затем `/retry ID` после исправления причины.

Новую модель через уже поддерживаемого провайдера можно добавить настройкой без изменения кода. Совершенно новый API-провайдер требует адаптера в `app/ai.py`, проверки в `app/policy.py`, подключения секрета и теста протокола. Произвольный URL API через Telegram не вводится. Многие дополнительные модели можно подключить через уже встроенный OpenRouter, если они поддерживают нужный формат ответа.

Официальная документация: [OpenAI](https://developers.openai.com/api/docs/), [Gemini](https://ai.google.dev/gemini-api/docs/models), [Groq](https://console.groq.com/docs/models), [DeepSeek](https://api-docs.deepseek.com/), [Mistral](https://docs.mistral.ai/), [OpenRouter](https://openrouter.ai/docs/).

## 4. Настроить всё через Telegram

Откройте `@suominews_bot`, отправьте `/start`. Кнопками «Новости» и «События» выбирается канал. Настройки разделены на расписание, темы и фильтры, текст, фото и ИИ. Числовые параметры можно менять кнопками «−/+», варианты — переключать, точные значения — вводить командой `/set`.

Для новостей отправьте по одному:

```text
/channel news
/set language українська
/set image_mode source_generate
/set image_order openai,gemini
/set require_image on
/set image_daily_limit 3
/set daily_limit 12
/set interval_minutes 60
/set window_start 08:00
/set window_end 22:00
```

Для событий:

```text
/channel events
/set language українська + suomi
/set event_cities Helsinki,Espoo,Vantaa
/set event_horizon_days 30
/set image_mode source_generate
/set require_image on
/set image_daily_limit 3
/set daily_limit 20
/set interval_minutes 30
```

`require_image on` оставляет материал в очереди, если фото получить не удалось. `off` разрешает текстовую публикацию после неудачной попытки. Лимит генерации считается **по API-попыткам**, включая ошибки и превью, отдельно по каждому каналу. Начальный лимит — 3 попытки в сутки на канал; он не ограничивает использование готовых фотографий источников. При двух провайдерах две попытки одного материала могут израсходовать две единицы лимита.

Фото: RSS/API → изображение статьи → генерация OpenAI → генерация Gemini, согласно настройке. Если нет ни одного ключа генератора, это отображается в очереди. Сгенерированная картинка подписывается как иллюстрация ИИ. Фотография источника получает указание источника/автора. Разрешение на использование фото проверяйте по условиям источника; отключение фото конкретного источника: `/sourceimages ID off`.

Дополнительные примеры:

```text
/set free_only on
/set event_languages uk,fi,en
/set weekdays 1,2,3,4,5,6,7
/set categories news,ukraine,sport,children,transport,other
/set exclude_words футбол,хокей
/set signature Більше корисного про життя у Фінляндії
/set silent on
/set review_provider groq
```

Фильтр `event_languages` относится к языкам самого мероприятия, указанным организатором, а не к переводу поста. При активном фильтре событие без метаданных о языке не подходит. `free_only on` требует подтверждённой бесплатности. Очистить строковый фильтр: `/set exclude_words -`. Вернуть параметр к начальному значению: `/reset ИМЯ`.

Порядок проверки первых материалов:

1. `/collect` запускает задание Scheduler и быстро возвращает ответ в Telegram.
2. Через несколько минут `/stats`, `/queue` или `/failed`.
3. В очереди нажмите «Превью»: пост придёт в личный чат.
4. Проверьте текст, фото и подпись нужного канала; «Опубликовать» отправит пост в канал.
5. `/auto_on` включает автоматическую публикацию **выбранного** канала. `/auto_off` выключает её.

Чувствительные новости, отсутствие даты/места, неуспешная ИИ-проверка и другие ограничения оставляют материал для модерации. Ручная публикация обходит лимиты и часы публикаций, но не разрешает отправить отменённое/прошедшее событие или событие без подтверждённой даты. Если дата или место официального события изменились, требуется новая ручная проверка.

Для анонса из RSS без машинно-читаемой даты администратор может внести проверенные данные:

```text
/event ID | 2026-11-01T18:00 | Helsinki | Название места, точный адрес | безкоштовно
```

Время без смещения трактуется как Europe/Helsinki. Команда работает только с материалом `pending`; ID виден в очереди. Ручная правка требует ручной публикации. `/retry ID` повторяет подготовку после смены языка, модели или исправления ключа. `/ask Допоможи придумати коротший заголовок: ...` вызывает редакционного помощника.

## 5. Источники и покрытие событий

Полный каталог с адресами: [SOURCES-RU.md](SOURCES-RU.md). Встроены больше 20 новостных RSS-лент. Несколько тематических лент могут принадлежать одной редакции; это не 20 независимых СМИ.

События: открытые городские API Helsinki Linked Events и Espoo Events, выборка Вантаа из Linked Events, RSS Ассоциации украинцев в Финляндии и Pro Ukraina. Городские API объединяют библиотеки, музеи, культурные центры и других организаторов. Полнота Вантаа ограничена тем, что передано в Linked Events; полный календарь Eventz/Townbase не подключён без отдельного API-доступа. Закрытые группы Facebook, частные чаты, страницы без RSS/API и личные Telegram-чаты не читаются.

Собираются будущие анонсы в заданном горизонте. Уже начавшиеся постоянные выставки и родительские записи повторяющихся событий не выдаются за новые мероприятия. Календари обходятся постранично, а обработка ограничена размером партии и бюджетом времени. Бот не обещает найти или опубликовать буквально все мероприятия в интернете.

Добавление нового RSS через Telegram:

```text
/channel events
/addsource Организация | https://example.org/feed/ | events
```

Бот выдаст ID. После проверки источника включите его через `/enable ID`. Для новостей используйте категорию `news`, `ukraine`, `sport`, `children` или `transport`. В `/sources` есть страницы, переключатели и последняя ошибка сбора. Новостной анонс, распознанный как событие, перенаправляется в очередь событий.

## 6. Обслуживание и скорость

Новости собираются каждые 15 минут; события — со сдвигом на 7 минут, чтобы снизить одновременную нагрузку. Публикационный интервал не может быть точнее частоты Scheduler. Расписание сбора меняется в Cloud Shell:

```bash
cd "$HOME/projects/bot"
PROJECT_ID=winged-ratio-377512 \
COLLECT_SCHEDULE='*/30 * * * *' \
EVENTS_SCHEDULE='7,37 * * * *' \
bash scripts/configure-scheduler.sh
```

Команда `/collect` использует роль `roles/cloudscheduler.jobRunner`, которую добавляет обновление. Длительный сбор выполняется отдельным запросом, а не внутри Telegram webhook. HTTP-соединения переиспользуются; Firestore вынесен из цикла обработки запросов; источники загружаются параллельно с ограничением. Холодный старт Cloud Run всё ещё возможен при `min-instances=0`. Постоянно включённый экземпляр можно настроить отдельно, но он увеличивает стоимость.

Повторная диагностика: `bash scripts/diagnose.sh`. Статус `needs_reconciliation` означает неопределённый результат отправки: сначала проверьте канал, потому что сообщение могло уйти. Автоматического повтора такого поста нет.

Очереди и неопубликованные фотографии занимают Firestore. Текущая версия не включает автоматическую очистку архива; при росте объёма потребуется политика хранения. ИИ-проверка сравнивает текст с данными источника и не заменяет независимую проверку фактов.
