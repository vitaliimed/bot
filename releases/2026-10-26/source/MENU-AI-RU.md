# Постоянное меню и управление ИИ

## Обновить работающий бот

Вставьте в Google Cloud Shell целиком:

```bash
(
set -e
cd "$HOME/projects/bot"
git pull --ff-only
PROJECT_ID=winged-ratio-377512 \
REGION=europe-north1 \
EVENTS_CHANNEL_ID=@eventhsl \
bash scripts/upgrade-all.sh
)
```

После успешного обновления отправьте `/start` или `/menu` в личном чате `@suominews_bot`.
Сервис проверяется до и после сборки. Существующие каналы, очередь, настройки, ключи и состояние автопубликации сохраняются. Скрипт выводит версию и команду возврата трафика к предыдущей ревизии. На сервере появятся шесть отдельных пустых секретов `bot-ai-*` для новых подключений; прежние секреты сохраняются.

Ключи в старой ревизии читаются из переменных окружения. Поэтому откат к старому коду **не сохраняет поведение удаления подключения**, введённое этим обновлением: старая ревизия может использовать свой старый ключ. Для отзыва самого ключа используйте кабинет провайдера.

## Кнопки остаются под полем ввода

- «Новости» / «События» выбирают канал. Текущий канал отмечен галочкой.
- «Очередь», «Собрать», «Настройки», «ИИ», «Источники», «Фото», «Статистика», «Ошибки» работают с указанным на кнопке каналом.
- «Включить авто» меняется на «Выключить авто» после изменения состояния.
- Кнопки внутри настроек показывают текущее и следующее значение. Числа меняются через −/+.
- Нажатая панель настроек обновляется в том же сообщении. Если сообщение нельзя отредактировать, бот отправляет новую панель.
- Новые кнопки настроек привязаны к каналу, в котором были созданы. Нажатие старой карточки новостей после переключения на события не изменит настройки событий.
- Старые переключатели из предыдущей версии, где канал не был указан в данных кнопки, открывают новое меню без изменения настройки. Нажмите нужную кнопку уже в обновлённой панели.
- Повторная доставка одного нажатия не переключает значение обратно. Публикации по-прежнему защищены от повторной отправки транзакцией.

Клавиатура запрашивается у Telegram как постоянная (`is_persistent=true`, `one_time_keyboard=false`). Клиент Telegram управляет её отображением; при необходимости нажмите значок клавиатуры рядом с полем ввода или отправьте `/menu`. Изменения другого администратора отражаются при следующем взаимодействии с ботом.

## Подключить ключ через Telegram

1. Нажмите «ИИ» или отправьте `/ai`.
2. Выберите OpenAI / ChatGPT, Gemini, Groq, DeepSeek, Mistral или OpenRouter.
3. Нажмите «Добавить / заменить ключ».
4. Следующим сообщением пришлите **только API-ключ**. Ввод действует пять минут; `/cancel` отменяет его.
5. Бот сохранит ключ и попытается удалить входящее сообщение. Если удаление не удалось, он попросит удалить сообщение вручную.
6. Нажмите «Проверить текстовый ИИ». Это небольшой реальный запрос к выбранной текстовой модели, который может тарифицироваться провайдером. Проверка текста не проверяет генерацию изображения.
7. При необходимости нажмите «Включить в этом канале» и «Сделать первым».

Пересборка и перезапуск сервера после добавления ключа не нужны. Сам ключ хранится в Google Secret Manager; в Firestore сохраняются только ссылка на версию и служебные поля. Он не показывается в ответах бота и не попадает в Git. Новый ключ не расходуется автоматически при сохранении: его начнут использовать последующие запросы согласно настройкам каналов.

Диалоги с ботами — облачные чаты Telegram. Удаление сообщения не превращает такую передачу в секретный чат. Альтернатива, если не хотите передавать ключ Telegram:

```bash
cd "$HOME/projects/bot"
bash scripts/connect-ai.sh openai
```

Или `bash scripts/connect-ai.sh all`. Скрипт скрывает ввод. Пустой Enter сохраняет текущее подключение. Новый скрипт работает после обновления сервера, записывает тот же тип подключения и тоже не перезапускает сервис. Если запись подключения не удалась, проверьте `/ai`: добавленная версия секрета может остаться в истории, не став активной.

## Где получить ключ

| Провайдер | Кабинет |
|---|---|
| OpenAI / ChatGPT | https://platform.openai.com/api-keys |
| Google Gemini | https://aistudio.google.com/api-keys |
| Groq | https://console.groq.com/keys |
| DeepSeek | https://platform.deepseek.com/ |
| Mistral | https://console.mistral.ai/ |
| OpenRouter | https://openrouter.ai/keys |

Подключается API провайдера. Подписка на пользовательский чат не является API-ключом. Для OpenAI расходы API отдельны от подписки ChatGPT. Проверьте доступ к модели, баланс и лимиты в своём кабинете.

## Отключить ИИ или удалить подключение

| Действие в карточке ИИ | Что изменится |
|---|---|
| «Отключить в этом канале» | Провайдер перестаёт использоваться для новых текстовых запросов, `/ask`, проверки и генерации изображений выбранного канала. Ключ и второй канал сохраняются. |
| «Включить в этом канале» | Снова разрешает провайдера. Для текста он также должен быть в `ai_order`, для изображений — в `image_order`. |
| «Сделать первым» | Включает провайдера в этом канале, добавляет в очередь текста и ставит перед остальными. Очередь генерации изображений отдельно в настройках фото. |
| «Удалить подключение в обоих каналах» | После подтверждения бот прекращает использовать этот ключ во всём боте. Старый ключ из окружения Cloud Run автоматически не подхватывается. |

Удаление подключения **не отзывает ключ в кабинете провайдера и не уничтожает старые версии в Secret Manager**. Оно удаляет его из использования ботом. Для полного отзыва ключа удалите его также в кабинете провайдера. Уже начатый запрос может завершиться после отключения. Повторное подключение — через «Добавить / заменить ключ» или `connect-ai.sh`.

Если отключённый ИИ был назначен проверяющим, автоматическая публикация ждёт проверки. Выберите другого проверяющего в «ИИ → Порядок, проверяющий, таймаут». Проверка не выключается автоматически вместе с провайдером.

Ключи общие для новостей и событий. Порядок, модели, проверяющий и список отключённых провайдеров отдельные для каждого канала. Администраторы с правом публикации могут менять настройки своего канала. Добавлять/заменять/удалять **общие ключи** может владелец основного канала `@suominewsua`; при режиме доступа по ID — назначенный `ADMIN_ID`. Личный ID для режима владельца канала указывать не нужно.

Команды для точной настройки:

```text
/channel news
/set ai_order openai,gemini,groq,deepseek,mistral,openrouter
/set disabled_ai deepseek,mistral
/reset disabled_ai
/set image_order openai,gemini
```

Отправляйте команды по одной. `disabled_ai` — список отключённых в этом канале; `/reset disabled_ai` разрешает всех, но не восстанавливает удалённые ключи. Новый провайдер, которого нет в меню, требует адаптера API в коде. Новая модель уже поддерживаемого провайдера добавляется через «Модель текста»; для изображения — через настройки фото.

## Почему пост не опубликован

В `/queue` у материала появилась кнопка «Статус / почему не опубликовано». Также можно отправить `/status ID`.

При нажатии «Опубликовать» бот показывает статус конкретного материала вместо общего «Не опубликовано; проверь статус». Указываются отсутствие обязательного фото, даты или места, начало/отмена события, изменение данных у источника или невозможность проверить источник. Для автопубликации отдельно показываются выключенный режим, фильтры, расписание и лимиты. При успехе показывается ссылка на пост в публичном канале.

`needs_reconciliation` означает, что подтверждение Telegram не получено. Сначала проверьте канал: сообщение могло уже уйти. Повторная отправка остаётся заблокирована; это не исправляется включением авто или повторным нажатием старой кнопки.

## Проверка после обновления

1. `/start`: постоянная клавиатура появилась.
2. Переключитесь между каналами: галочка, подписи и состояние авто соответствуют выбранному каналу.
3. `/ai`: существующий Gemini виден. Остальные подключайте по необходимости.
4. Подключите ключ и проверьте текстовый ИИ. Если ошибка 401/403 — ключ или доступ, 429 — квота/баланс, 400/404 — модель или формат запроса; при таймауте можно выбрать резервного провайдера.
5. `/queue` → «Статус» → «Превью» → «Опубликовать» для проверенного материала.

Диагностика Cloud Shell: `bash scripts/diagnose.sh`. Она отдельно показывает старые привязки окружения и актуальные подключения бота, без значений ключей.

Реальные API-ключи и публикации не используются в автоматических тестах. Проверки моделируют два экземпляра Cloud Run, удаление подключения, авторизацию, старые кнопки и блокировки публикации.

Официальные технические справочники: [клавиатура Telegram](https://core.telegram.org/bots/api#replykeyboardmarkup), [удаление сообщения](https://core.telegram.org/bots/api#deletemessage), [права Secret Manager](https://docs.cloud.google.com/secret-manager/docs/access-control).
